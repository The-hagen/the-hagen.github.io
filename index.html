The Oslo Børs model

A research pipeline that, once a month, forecasts next month's return for every stock on Oslo Børs worth more than NOK 1 billion, ranks them, and flags the ten highest as that month's picks.

It is a fully automated pipeline that runs on the 1st of each month. When a run finishes, the latest result is published to this website and the page updates itself, so the numbers here always come from the most recent run.

The model is a random forest (200 trees) trained on the last eight years of monthly data and about 185 inputs per stock. I compared it against a neural network and LightGBM while building it; the random forest is what the monthly run uses.

How a monthly run works

  1. FetchPrices from Yahoo, macro series from FRED and Statistics Norway (oil, gas, rates, currencies, VIX, salmon and timber prices), and short positions from Finanstilsynet. Every fetch is counted, so a run that only got 40 of 200 tickers cannot pass as a healthy one.
  2. Check the data is readyPrices have to reach the last trading day of the previous month. Anything behind gets one targeted re-fetch. If more than 10% of stocks, or the OSEBX or S&P 500 index, are still behind, the run stops before it fits anything.
  3. Build featuresAbout 185 per stock per month: momentum and reversal, volatility, liquidity, size and value characteristics from the Jensen-Kelly-Pedersen factor set, short interest, earnings timing, each stock's exposure to oil, rates and currencies, and a geopolitical-risk index. They are stored before fitting, so a failed fit doesn't lose them.
  4. FitThe random forest is trained on a rolling eight-year window, using only data that was available at the time. The target is next month's return including dividends.
  5. Forecast and rankEvery stock in the universe gets a forecast, including stocks with gaps in their history (they are filled from the training window's medians rather than dropped). The ten highest are the picks.
  6. Report and publishThe ranking is pushed to this site. A private diagnostics report checks data freshness, feature drift and anomalies, and scores how last month's picks did once that month has closed. Then the database is backed up.

What it publishes, and what it doesn't

The public file has eight fields per stock: rank, ticker, name, sector, forecast, signal, whether it is a pick, and last month's rank. Which inputs drive the model is left out on purpose. That rule is enforced in code with a whitelist the publish step checks on every run, because this site's repository is public and its history is permanent.

Nothing fails quietly. A run that hits an error still publishes its ranking, but the problem is flagged and logged with what went wrong.

This is research code, not investment advice. The forecasts are out-of-sample, but one exchange over about a decade is a research baseline, and a ranking that looks confident can still be wrong for months at a time.
